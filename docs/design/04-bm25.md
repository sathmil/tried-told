# Design Decision 04: BM25 Scoring

Status: decided, Milestone 1
Date: 2026-07-29

## Decision

Implemented Okapi BM25 from scratch in `internal/bm25`:

```
score(D,Q) = Σ_t idf(t) · f(t,D)·(k1+1) / (f(t,D) + k1·(1-b+b·|D|/avgdl))
```

- **IDF variant:** smoothed, `log((N-df+0.5)/(df+0.5) + 1)` — always >= 0. We
  don't remove stopwords (design doc 02), so IDF has to self-suppress common
  terms toward zero rather than letting them actively penalize a document.
- **k1, b:** `Params{K1, B}` passed into `Search`, not hardcoded — literature
  defaults `k1=1.5, b=0.75` live in `DefaultParams`, tunable later via the
  evaluation harness (not the held-out test set).
- **`index.Index` extended** from a bare postings map into a struct also
  holding `DocLen []int`, `AvgDocLen float64`, `N int` — document length is a
  property of the document, not any term, so it's stored once per DocID
  rather than duplicated into every posting. This also required tightening
  `BuildIndex`'s invariant from "strictly ascending IDs" to "contiguous IDs
  starting at 0," since `DocLen` uses DocID directly as a slice index (as do
  `IndexDoc`/`DocMeta` already, per design doc 01).
- **Search** tokenizes the query, walks each query term's postings, and
  accumulates each posting's contribution into `scores[DocID]` — this is the
  concrete reason a `Posting` must carry `DocID` and not just `Freq` (design
  doc 01): contributions from different query terms have to be attributed
  back to the same document to sum into one total. Results are sorted by
  score descending, ties broken by ascending DocID for determinism.

## Key properties (proven via tests, not just asserted)

- TF contribution saturates at `k1+1` as frequency grows — verified directly
  in `TestTermScore_SaturatesAtK1Plus1`.
- IDF is never negative even for a term in every document — verified in
  `TestIDF_NeverNegative`.
- A rarer term has strictly higher IDF than a common one, all else equal —
  `TestIDF_RarerTermScoresHigher`.

## Alternatives considered

- **Unsmoothed IDF** (no `+1`). Rejected: goes negative for terms in over
  half the corpus, which would actively penalize documents for containing a
  common word — undesirable given we rely on IDF instead of stopword removal.
- **Doc length stored per-posting** instead of per-DocID. Rejected: doc
  length doesn't vary by term, so storing it once avoids duplication and
  keeps a single source of truth.
